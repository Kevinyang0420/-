- **路线乙**：用 OpenSSL 生成 CSR（我可以给你现成命令，见第三节）

下载到的 `.cer` 要和私钥合成 `.p12`（带密码）。

## 二、要塞进 GitHub Secrets 的（👤 你做，5 分钟）

仓库 → Settings → Secrets and variables → Actions → New repository secret

| Secret 名 | 内容 | 怎么得到 |
|---|---|---|
| `IOS_CERT_P12_BASE64` | 证书 .p12 的 base64 | `certutil -encode cert.p12 out.txt`（去掉首尾行） |
| `IOS_CERT_PASSWORD` | .p12 的密码 | 你导出时设的 |
| `IOS_PROFILE_APP_BASE64` | 主 App 描述文件 base64 | 同上，对 `.mobileprovision` |
| `IOS_PROFILE_KB_BASE64` | 键盘描述文件 base64 | 同上 |
| `IOS_TEAM_ID` | Team ID | Membership 页 |

> base64 编码我可以帮你跑，文件放共享盘就行。

## 三、Windows 上生成 CSR（如果走路线乙）

```bash
openssl genrsa -out ios_private.key 2048
openssl req -new -key ios_private.key -out ios.csr \
  -subj "/emailAddress=你的邮箱/CN=Kevin Yang/C=HK"
```

拿 `ios.csr` 去开发者后台换 `.cer`，下载后合成 `.p12`：

```bash
openssl x509 -in distribution.cer -inform DER -out dist.pem -outform PEM
openssl pkcs12 -export -inkey ios_private.key -in dist.pem -out dist.p12
```

🚨 `.p12` 和私钥**别提交进仓库**，只放 GitHub Secrets。

## 四、CI 我会改成什么（我做）

新增一个 workflow：`ios-release.yml`，跟现有的不签名流程**并存不冲突**：

1. 从 Secrets 还原证书和描述文件到 runner 的钥匙串
2. `xcodebuild archive`（带签名，`CODE_SIGN_STYLE=Manual`）
3. `xcodebuild -exportArchive` 出 App Store 用的 ipa
4. 用 `xcrun altool` / `xcrun notarytool` 上传到 App Store Connect
5. **收工闸**：验证产出的 ipa 里**主 App 和键盘扩展都被签名**
   （`codesign -dv` 两个都查，只查主 App 是假检查）

🚨 第 5 条是关键：**只验主 App 签名 = 又一次"闸门看的范围不对"**。
键盘扩展签没签上，是这次的核心问题，闸门必须专门查它。
